# Git operation API

`src/core/operations.ts` exports the following APIs. Every function starts with `(repo: Repository, git: GitRunner, ...)`. Callers authorize workspace trust before mutations, present the exact repository and target, retain drafts on failure, and refresh after success or uncertain failure. `prepareWrite` comes from `status.ts`; capture it before user confirmation. All mutations share `withWrite` with whole-file staging and commits, serializing validation and execution by common directory. Git's locks remain authoritative against other processes; external edits can still race after validation.

- `readHunks(repo, git, file, staged): Promise<HunkReview>` captures a precondition and returns independently selectable text hunks. `applyHunks(repo, git, reviewOrId, ids): Promise<void>` stages unstaged hunks or unstages staged hunks. It accepts only IDs from the captured patch; it never accepts arbitrary patch text from UI messages. Binary files, renames, mode changes, symlinks and gitlinks use explicit whole-file actions. New text files are supported. Reviews expire after an apply attempt and are bounded by count and memory.
- `listBranches(repo, git): Promise<BranchTarget[]>` returns local/remote refs and immutable target OIDs. `createBranch(repo, git, name, start: BranchTarget, precondition, { switchTo? }?)` and `switchBranch(repo, git, target: BranchTarget, precondition)` revalidate the chosen ref. Switching only supports local branches; selecting a remote branch first requires creating a named local branch. Dirty state is preserved by Git's ordinary switch safeguards; no force is used. Ignored-file overwrites and recursive child checkout are explicitly disabled.
- `listStashes(repo, git): Promise<StashEntry[]>`; `createStash(repo, git, message, paths: string[], includeUntracked, precondition)` requires explicit file paths. It refuses unrelated staged files because Git's pathspec stash still captures the complete staged index; the user must unstage those files or select them explicitly. Selected untracked files require `includeUntracked`. `applyStash(repo, git, entry, restoreIndex, precondition)` preserves the stash even on success; `dropStash(repo, git, entry, precondition, confirmation: true)` requires explicit destructive confirmation and unchanged stash identity.
- `listRemotes(repo, git): Promise<RemoteTarget[]>` is local configuration inspection, with credentials redacted from effective fetch/push URLs after Git's URL rewrites. `lastFetchedAt` is present only for successful fetches observed by this service session; unknown history is not fabricated. `fetchRemote(repo, git, remote, precondition, { signal? }?)` fetches heads into that remote's tracking namespace without tags, pruning or recursive submodule work. `pushBranch(repo, git, remote, destinationBranch, precondition, { signal? }?)` pushes the reviewed HEAD to an explicit remote branch without force or implicit tags. `pullFastForward(repo, git, remote, branch, precondition, { signal? }?)` explicitly fetches that branch and performs a fast-forward-only merge; a diverged branch is rejected. Signals are reserved for explicit user cancellation of network work, never selection changes; uncertain outcomes are reported without retrying.
- `readOperationState(repo, git): Promise<OperationState>` reports conflicts and merge/rebase/cherry-pick/revert/bisect state without starting operations.
- `readHistoryPage(repo, git, options?): Promise<HistoryPage>` supports an immutable revision anchor, optional file path, bounded page size and offset. `readCommitDetail(repo, git, revision): Promise<CommitDetail>` returns metadata, parents, message and changed paths. `readRevisionDiff(repo, git, from, to, file?): Promise<string>` resolves both revisions locally to commit IDs before showing a safe diff.

Readonly calls never authorize network retrieval. Network happens only in the named remote mutations. URL changes, moved selected branch refs/stash entries, stale HEAD/index/path content, unknown hunk IDs, path traversal, and repository-boundary violations are rejected. Dropping stash is intentionally separate from applying it. No force push, hard reset, clean, automatic stage-all, automatic stash-pop, or blind retry API is exposed.

`desktop/main/git-service.ts` adapts these APIs to the renderer contract. `GitService.handlers` contains Git handlers except the recoverable-discard handler supplied by the file service. Every mutation rechecks workspace trust. Sensitive operations use native confirmation, and remote confirmations display backend-resolved destinations. Tokens are single-use, bound to action, repository and exact path set. Hunk IDs point to backend-owned patches.

`git.diff` captures a stable before/after fingerprint and returns a review ID. Whitespace-filtered presentations cannot authorize hidden changes. `git.prepare` requires the displayed basis: a matching diff/hunk review, a retained status generation, or `none` for operations not derived from viewed file content. The status publisher calls `recordStatusBasis(repositoryId, generation, precondition)` with a snapshot captured alongside that status observation, never a snapshot taken after the user clicks an action. A generation cannot be rebound to newer contents. The latest basis is retained for up to sixteen recently recorded repositories; missing or superseded bases require refresh.

`consumeReview(repositoryId, token, action, paths?)` exposes the same safeguards to recoverable discard. `clearReviews()` invalidates all handles and status bases when trust or workspace identity changes. `git.cancel` explicitly cancels the one running network operation allowed per repository. Selection and review invalidation never cancel writes. `GitOperationError` preserves redacted stdout/stderr and exit code for local failure detail; the adapter maps failures to stable renderer codes and invalidates repository observations after write attempts. Workspace trust is checked again at every Git write invocation, including after asynchronous freshness scans.
