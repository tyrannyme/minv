# Workspace files and search API

`src/core/files.ts` exports `WorkspaceFiles`, created with `await WorkspaceFiles.create({ roots: string[], recoveryDirectory: string, repositoryRoots?: string[], maxTextBytes?: number, largeTextBytes?: number })`. Roots must be explicitly approved by the desktop caller. `files.roots` contains stable `{ id, path }` identities. Repository roots identify boundaries for cross-repository operations. No symlinks are followed, no `.git` metadata is editable, and paths are root-relative.

Desktop IPC should keep a single service per open workspace and invoke:

- `list(rootId, path = '', { limit?, exclude? }?)`: immediate children only, `{ entries, complete }`. Entries have `name`, `path`, `kind` (`file`, `directory`, `symlink`, `other`), and `size`. Excludes are separate browse-only globs.
- `read(rootId, path)`: `FileDocument`. Text documents contain `id`, `rootId`, `path`, `kind: 'text'`, `text`, `encoding` (`utf8`, `utf16le`, `utf16be`), `bom`, `eol` (`lf`, `crlf`, `cr`, `mixed`, `none`), `scope` (owning repository path), `fingerprint`, `size`, and `large`. Binary/over-limit documents have metadata and `kind: 'binary' | 'large'`; they do not contain truncated editable text. Default hard text limit is 16 MiB; reduced-tokenization threshold is 2 MiB.
- `save({ rootId, path, text, encoding, bom, expectedFingerprint })`: compare disk content against the fingerprint from `read`, atomically replace with exact requested encoding/BOM, and return the new text document. No line-ending normalization. `FileConflictError` means the caller must preserve its buffer and offer a comparison. No force-overwrite flag exists. Saves retain a recoverable backup; external processes do not share an application transaction lock, and the final compare/rename has an unavoidable OS race.
- `recover({ documentId, rootId, path, text, encoding, bom, expectedFingerprint })`: durably persist a dirty-buffer draft independently of caches. `recoveries()` returns saved drafts; `removeRecovery(documentId)` removes one only after explicit successful save/discard. Drafts survive missing source files and are not applied automatically.
- `createFile(rootId, path, text = '')` and `createDirectory(rootId, path)`: exclusive create, never overwrite existing content.
- `prepareTransfer('copy' | 'move', sourceRootId, sourcePath, targetRootId, targetPath)`: return `{ token, sourceScope, targetScope, requiresConfirmation }`. Files only; directory moves/copies require an external tool. Show both scopes when confirmation is required. `transfer(token, confirmed = false)` consumes the preparation, rechecks disk state, and refuses collisions or silent repository-boundary crossings.
- `deleteFile(rootId, path, expectedFingerprint)`: recoverable file deletion, returns a backup id; directories and symlinks are refused. `backups()` lists recoverable backups and `restoreBackup(id)` restores exclusively if the original destination is absent. `backup(rootId, path, expectedFingerprint?)` creates a durable pre-discard backup without changing the file.
- `absolutePath(rootId, path)`: validated existing file/directory path for reveal or external handoff; does not follow symlinks.

Errors include `FileConflictError` (code `FILE_CONFLICT`) and `FileBoundaryError` (code `FILE_BOUNDARY`). The service serializes its own writes. Repository identity is the deepest declared repository root containing a path, so worktrees/submodules retain distinct scope. The caller must pass current catalog repository paths when creating the service, or call `setRepositoryRoots(paths)` after discovery.

`src/core/search.ts` exports `WorkspaceSearch`, constructed with `new WorkspaceSearch(files, { rgPath?: string })`:

- `search({ rootIds?, paths?: {rootId,path}[], query, regex?, caseSensitive?, includeIgnored?, includeHidden?, exclude?, maxResults?, maxFileBytes?, signal? })` returns `{ matches, complete, cancelled, errors }`. Match entries contain `rootId`, root-relative `path`, one-based `line`, zero-based `column`, `text`, (UTF-16 code units), and UTF-8 byte `matchLength`. Queries are explicit local reads; no shell is involved. Ignore files apply by default; `includeIgnored` enables `rg --no-ignore`. Search excludes do not alter browse or Git visibility. Default cap: 1,000 matches and 2 MiB per file. `complete` covers that requested size/ignore policy, never all Git changes.
- `findFiles({ rootIds?, query?, includeIgnored?, includeHidden?, exclude?, maxResults?, signal? }, onBatch?)` returns `{ files, complete, cancelled, errors }`. File entries are `{ rootId, path }`; batches arrive incrementally, with no startup crawl. Its reusable filename index stores only encountered paths in memory and is explicitly refreshed on each call; edits are not claimed current until rescanned.

Cancellation terminates the read subprocess. Regexes run in ripgrep's bounded Rust regex engine (no PCRE option), not the UI JavaScript thread. Output and result caps produce `complete: false`; stderr errors remain visible. Missing ripgrep produces a visible error rather than a silent empty result. No files are searched outside approved roots or through symlinks.

`cachedFiles(query?)` returns the incremental filename index immediately as a deliberately partial (`complete: false`) navigation hint. It reflects the last explicitly requested policy for each root and may contain stale paths; call `findFiles` to revalidate. Document ids derive from canonical absolute paths, so equivalent relative spellings retain the same identity.

Recovery retention is bounded by `maxRecoveryBytes` (default 512 MiB) and `maxRecoveryRecords` (default 1,024). A capacity failure preserves every existing dirty draft and reports an actionable error; drafts are never evicted automatically. Each draft is additionally bounded to twice the editable-file byte limit. `removeBackup(id)` explicitly deletes a resolved backup; `removeRecovery(documentId)` clears an explicitly resolved draft. The storage directory is private (0700), and payloads/records are private (0600). Capacity includes retained backups and orphan temporary files, so a prior interrupted write cannot silently bypass the bound.

On Linux, search pins each requested directory using an open descriptor retained while ripgrep runs, and uses `/proc/<host pid>/fd/<descriptor>` as subprocess cwd. Explicit file scopes become an exact filename include while traversing `.` without symlink following. Scope identity is validated before and after results; changed roots produce incomplete results with an error. Other platforms currently use before/after scope checks without the Linux pinned-cwd guarantee and are not release-supported. Invalid UTF-8 filenames are rejected instead of becoming replacement-character aliases.

## Desktop host adapter

`desktop/main/file-service.ts` exports `FileService`, with `handlers` matching the authoritative renderer contract. Context supplies `files`, `search`, `getRepository`, optional `getRepositories` (required for whole-workspace enumeration), `isTrusted`, native `confirm`, `emit`, and `trackFile`. Optional `canBrowseRepository(id)` explicitly permits a non-Git folder row: this never approves an ancestor or a location outside `files.roots`. Optional `browseExclude` and `searchExclude` keep the policies separate.

Passive file/list/search and recovery inspection work without workspace trust; file mutations require current trust. `onFileChanged(key)` reports disk versions/deletion without replacing dirty text or advancing its save base. `persistDraft`, `recoveries`, and `session` support app lifecycle integration. Recovery drafts from previously opened disk versions remain valid after a separate comparison read.

Recoverable Git discard is available when context supplies `git`, `consumeGitReview(repositoryId, token, 'discard', paths)`, and `invalidate`. It consumes the action/path-bound Git review, confirms through the host, creates backups for all existing selected regular files, revalidates the repository after backups, restores tracked files from the index, and recoverably deletes selected untracked files. Directory, symlink, gitlink, and unresolved index entries are refused. No broad clean/reset command is used.
