What you open it for

Open it, glance, close it.

See exactly what your agent changed.

VS Code's own Source Control, untouched: side-by-side diffs, staging by hunk, a commit box, the graph, push and pull. Pick a submodule and its changes are right there.

  • Ctrl⇧G Source Control
  • Ctrl⏎ Commit

Which branch is that submodule on?

The Repositories list is on by default and shows every submodule with its branch. Minv opens up to 256 of them where VS Code stops at 10, so large workspaces just work.

  • Feature branches stand out at a glance
  • A * marks uncommitted work

Read the README the way GitHub will show it.

Markdown renders beside the source with images, tables and code, and updates as you type. Fix the typo and commit without leaving the window.

  • CtrlK V Preview to the side

Find the file. Read it. Run one command.

The Explorer, Quick Open, search across files, and the integrated terminal, all where your hands expect them.

  • CtrlP Open a file
  • Ctrl⇧F Search
  • Ctrl` Terminal

How it's made

A pinned Code-OSS commit and one small folder of changes.

No long-lived fork drifting away from upstream. Every build starts from Microsoft's MIT-licensed Code-OSS source at a pinned commit and applies the same changes, in CI, from scratch.

fork/
  upstream.json          Code-OSS 1.137.0, pinned to one commit
  strip.json             features that are never registered
  extensions-remove.json built-in extensions that aren't shipped
  product.json           name, data folders, quiet defaults
  extensions/minv-theme  Minv Dark and Minv Light
  patches/               ten small, commented patches

Install

One package. Nothing to sign into.

Debian, Ubuntu (.deb) Fedora, RHEL (.rpm) Windows (installer) Any distro (AppImage) 
# Debian, Ubuntu
$ sudo apt install ./minv-linux-x64.deb
# Fedora, RHEL, openSUSE
$ sudo dnf install ./minv-linux-x64.rpm
# Windows: run minv-win32-x64-setup.exe. Then open any folder
$ minv ~/your/workspace

x64 with Git installed. Settings live apart from VS Code's. Unsigned, so Windows asks before the first run, with no auto-update: install a newer package to update. All releases and checksums
